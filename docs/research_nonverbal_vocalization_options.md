# Local Non-verbal Vocalization Research

## Decision

Nastech TTS should add a **lazy optional Nastech Vocal Events Pack** rather than enlarge the measured Nastech Voice Core. The active compatible route uses a separate local English Turbo renderer for vocalization-capable tags; Nano remains a documented future CPU-focused route once its matching runtime interface is available. The integration retains the existing Nastech Voice Core expression compiler as an explicit fallback and must never describe a mapped cue as a guaranteed natural event.

## Evidence

| Option | Evidence | Fit for Nastech TTS | Boundary |
|---|---|---|---|
| Chatterbox Turbo | The official repository and model card document a 350M English model under MIT terms with native paralinguistic tags. The installed compatible runtime exposes Turbo's local loader. | Active optional local renderer for natural laughter, chuckles, sighs, coughs, gasps, and related tags. It is externalized as an on-demand pack so the measured core remains within its 1 GiB budget. | English only. A local model download and a consented voice reference are required. The pack remains optional and offline after download. |
| Chatterbox Nano | The official Nano card describes a 110M English CPU-capable model with the same style of paralinguistic tag support. | Planned lower-memory event route after its matching runtime interface receives an acceptance test. | Not selected as the active loader because the installed compatible package exposes Turbo only. |
| Chatterbox Turbo ONNX | The official ONNX model card documents local ONNX inference. | Future alternate integration for suitable hosts. | Requires separate tested wrapper and acceptance evidence. |
| Fish Audio S2 / OpenAudio S1 | Official documentation lists native `[sobbing]`, `[crying loudly]`, `[laughing]`, `[yawning]`, `[screaming]`, and related effects. The public S2 source describes a 4B model under the Fish Audio Research License; the legacy S1 container documentation describes non-commercial model-weight terms. | Evidence that real local crying and sobbing can be model-generated by a separate specialised renderer. | Not selected for the default Nastech pack: the model is too large for the compact CPU profile and its current model licence must be separately approved for the intended distribution. |
| NonverbalTTS dataset | The public dataset card lists Apache-2.0 and 6.26k audio/text rows; its accompanying paper reports 17 hours, 10 non-verbal types, and 8 emotion classes. | Appropriate research and potential fine-tuning evaluation source. | Do not bundle its clips or train a release until source provenance, speaker-consent scope, and all downstream distribution terms have been independently reviewed. |
| Deeply Nonverbal Vocalization dataset | It includes cries, laughter, coughing, yawning, throat-clearing, sighing, and screaming, but is explicitly CC BY-NC-ND 4.0. | Useful taxonomy reference only. | Not eligible for commercial Nastech TTS product distribution without separate rights. |
| ReCANVo | The publication describes naturalistic non-verbal recordings from minimally speaking participants. | Research context only. | Not an appropriate event-pack source: a vulnerable participant population and context-specific consent require a strict non-use boundary. |

## Implementation Commitments

The first Nastech Vocal Events Pack supports separate, auditable routing for **laugh**, **chuckle**, **cough**, **sigh**, **gasp**, **sniffle**, **groan**, and **throatclear**. It reports `native-event` only after a successful local event render. It marks **cry**, **scream**, and **yawn** as `core-expression-fallback` unless a separately approved local pack confirms a corresponding native tag through an acceptance test. The researched Fish Audio route proves that native sobbing and crying are possible, but it is deliberately excluded pending licence and high-resource deployment approval.

No recorded human event clips are bundled in this change. Nastech TTS must only accept a user-provided reference WAV when the operator confirms they have the necessary voice authorization.

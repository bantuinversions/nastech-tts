# Nastech Multilingual and Expressive Release Evidence

## Scope

This release evidence complements the neutral 30-minute English continuity test. It records two separate real local synthesis runs: an expressive English audition through the verified Nastech compact CPU runtime, and a Luganda technical preview through an explicitly configured, isolated local VITS provider pack. The evidence distinguishes **digital audio validity** from a **human language-quality claim**.

> The Luganda fixture proves that the configured local provider accepted the selected Luganda input and produced a valid Nastech delivery WAV. It does **not** prove native-speaker intelligibility, naturalness, dialect suitability, or a pure-Luganda quality threshold. Those require competent Luganda reviewer acceptance.

## Expressive English Evidence

The expressive source requests `<emotion name="sad">`, `<emotion name="angry">`, `<emotion name="happy">`, `<sound type="sigh" />`, `<sound type="cough" />`, and `<sound type="laugh" />`. The generated manifest, rather than a prose claim, is the authoritative record of how each request was compiled. The WAV is not a proxy recording and is generated by the real local runtime.

## Luganda Provider Evidence

The Luganda run uses the public `multilingual-tts/VITS-OpenBible-Luganda` multi-speaker VITS checkpoint, whose model card specifies Luganda data, a Coqui TTS local inference path, training-set speaker selection, and 22.05 kHz provider output.[1] Nastech invokes the model only through an operator-managed local command and converts its successful provider WAV to mono signed-16-bit PCM at 44.1 kHz before applying deterministic cleanup.

The provider model is a separate optional pack. Its published repository reports approximately 997,713,840 bytes of model storage, before its isolated Coqui-compatible CPU runtime.[2] It therefore is **not** bundled in the ≤1 GiB Nastech TTS core. The model card reports CC-BY-SA-4.0; any distribution must preserve applicable attribution and share-alike obligations.[1]

The pure-Luganda fixture source intentionally excludes English product names and typographic curly apostrophes. The local model emitted vocabulary warnings for both in the initial mixed-language probe, so that probe is not release evidence. The retained source rendered without a missing-character warning.

## Promotion Rule

Luganda may be surfaced as a `configured-local` **technical preview** only while the explicit provider configuration is present. It may advance to `verified-local` only when all the following are recorded:

| Requirement | Required evidence |
|---|---|
| Licence review | Attribution and share-alike distribution plan for the exact model, code, and audio fixture. |
| Local repeatability | Pinned isolated CPU runtime, model revision, selected speaker, source markup, manifest, WAV checksum, and resource measurement. |
| Digital audio integrity | Mono 16-bit PCM WAV at 44.1 kHz, valid duration, accepted peak/RMS/DC checks, and deterministic cleanup report. |
| Native language review | Competent Luganda reviewer checks intelligibility, pronunciation, orthography-to-speech handling, and dialect appropriateness using approved fixtures. |
| Disclosure | Public description identifies the exact provider/model, speaker scope, and any remaining limitations. |

Major Bantu-language targets across East and Southern Africa are cataloged in [BANTU_LANGUAGE_COVERAGE.md](../docs/BANTU_LANGUAGE_COVERAGE.md). A target marked `planned`, `research-candidate`, or `adapter-available` is not a working Nastech synthesis language.
